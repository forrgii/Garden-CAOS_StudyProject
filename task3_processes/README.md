# Задание 3: Умные цветы (Процессы и Очереди сообщений)

Данный проект представляет собой реализацию имитационной модели «Умные цветы» (Вариант 14) для третьего индивидуального задания. 

Реализация выполнена на оценку **8+ баллов**. В отличие от предыдущих заданий (где использовались потоки `pthread`), здесь приложение состоит из **трех независимых программ-процессов**, запускаемых отдельно. Взаимодействие между ними организовано асинхронно с использованием **именованных POSIX семафоров** и **очередей сообщений POSIX**.

## Архитектура решения

Программа разделена на три независимых исполняемых файла:
1. **`coordinator`** — процесс-менеджер. Создает все IPC-ресурсы (семафоры, очереди, разделяемую память), работает как глобальные часы (инкрементирует такты) и корректно удаляет все ресурсы ядра при завершении.
2. **`flower <id>`** — процесс цветка. Самостоятельно отслеживает влажность. При увядании отправляет заявку в общую очередь сообщений.
3. **`gardener <id>`** — процесс садовника. Слушает общую очередь, проверяет защитный интервал и отправляет команду на полив в личную очередь конкретного цветка.

## Синхропримитивы и Обмен данными (IPC)

Для обмена данными и синхронизации независимых процессов используются следующие механизмы:

### 1. Очереди сообщений POSIX (`mq_open`)
*   **`/flower_mq_req`** — общая очередь для заявок. Цветы пишут сюда структуру `Message` с типом `MSG_REQUEST`.
*   **`/flower_mq_res_<id>`** — индивидуальная очередь для ответов конкретному цветку (защита от «воровства» сообщений другими процессами). Садовник отправляет сюда тип `MSG_WATER_START` или `MSG_DEAD`.

### 2. Именованные семафоры POSIX (`sem_open`)
*   **`/flower_sem_req`** — счетный семафор. Сигнализирует садовникам о появлении новой заявки в очереди (реализует паттерн Producer-Consumer).
*   **`/flower_sem_res_<id>`** — бинарный семафор. Будит конкретный цветок, когда для него пришел ответ в его очередь сообщений.
*   **`/flower_sem_log`** — мьютекс для защиты вывода в консоль. Предотвращает смешивание строк от разных процессов.

### 3. Разделяемая память POSIX (`shm_open`, `mmap`)
Используется минимально, чтобы не нарушать архитектуру обмена через очереди. В разделяемой памяти лежит структура `SimState`, содержащая:
*   `current_tick` — глобальный счетчик тактов (нужен садовникам для проверки интервала перелива).
*   `stop` — флаг завершения симуляции.
